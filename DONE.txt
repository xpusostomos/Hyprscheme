== CORE API (complete, at upstream Lua parity) ==
- Handle model: windows, workspaces, monitors, groups, layer surfaces,
  notifications, timers, binds, rules, gestures, events — all opaque
  records with identity (=?) and staleness (alive?), no global
  registries (counted locks / guardians; destruction-driven release).
- Window/workspace/monitor query+action surface (full field parity:
  title, class, address, pid, geometry, state toggles, tags, layout
  info, group ops, monitor rules + hardware getters).
- Binds: token lists (hl-kbd/hl-key generators), all flags, devices,
  submaps (define/activate/exit/universal), mouse/click/drag, auto-
  consuming result protocol (ok/pass-event/request-release/error).
- Events: the full compositor event bus wired (34 events).
- Rules: window/layer/workspace rules with runtime enable/disable.
- Exec: (hl-exec! cmd . effects) — one function, plist rule object.
- Timers: one-shot + repeating, live pause/retime/cancel.
- Notifications: one-shot + full live-object surface (text/timeout/
  color/icon/font/pause/dismiss).
- Gestures: typed action values — hl-make-{workspace-swipe,move,resize,
  close,scroll-move,float,fullscreen,special,cursor-zoom}-gesture +
  hl-make-custom-gesture (start/update/finish); hl-gesture-add! returns
  a handle; removal by spec. Documented: bind-gestures.md.
- Custom layouts: recalculate/resize/window-open/window-close/layout-msg
  callbacks; resize falls back to recalculate; errors contained.
- Device config (hl-device-add!), permissions, animations, monitors,
  workspace rules, exec with rule object, screenshare/keyboard-key.
- hl-state (cross-reload state; the one accepted extension) with
  remove!.

== INFRASTRUCTURE ==
- Scheme machinery in real files: hyprscheme-{prelude,bootstrap,defun}.scm
  in src/config/scheme/, installed next to the plugin, read from disk at
  startup (plugin dir via dladdr; source tree + HYPRSCHEME_SCM_DIR as
  dev overrides). No embedded blobs; writeSchemeFile is gone.
- defun machinery (opt-in, one demo conversion so far): defun macro
  captures the arglist VERBATIM (syntax-case; pattern vars named
  formals/docstring so 'args/'doc stay literal) + docstring + source
  file (hl--load-source parameter, bound by the prelude's file loader)
  into hl--function-table (eq-hashtable, persistent env).
  (describe-function 'f) -> text; hl--describe-hooks for later layers.
- hyprctl scheme eval channel; per-generation environments (fresh env
  per reload, persistent API layer); watchdog (config-settable budget);
  crash-reporter integration; HYPRSCHEME_CONFIG override.
- Modifiers: mods are token lists everywhere (hl-kbd/hl-key generate
  them); no string parsing inside the API. Terminal dash = pure mod
  list ((hl-kbd "C-M-")).
- Exec: single (hl-exec! cmd . rules); no shell/raw split, no execvp.

== THE LOADER (init.scm owns the module list) ==
- init.scm is the ONLY list of modules, and the ONLY thing the host
  loads. Host.cpp names no module at all: it creates the kernel and
  registers the gsubrs, makes the generation, makes it CURRENT, then
  one evalFile(init.scm) — so init.scm's `use-modules` ARE the
  generation's environment, stdlib included. The 23-line useModule()
  list that duplicated init.scm's and could drift from it is GONE.
- init.scm's `in?` was a load masquerading as a probe. `resolve-module`'s
  second POSITIONAL arg is `autoload` (default #t) and `#:ensure` is a
  separate switch, so `(resolve-module name #:ensure #f)` still LOADED
  the file and answered "already in" for a module never loaded. Every
  module's body therefore ran TWICE on generation 1, and the macro's
  `use-modules` branch was dead code that never once executed.
- The probe is now `(resolve-module name #f #:ensure #f)` AND a
  `module-filename` check. Autoload off is not enough on its own: a
  module can exist with no file behind it. `(hyprscheme)` is the parent
  of every `(hyprscheme X)`, so the tree grows it as a directory module
  as soon as the first family is defined, and `reload-module` on it
  fails ("unknown file name for module"). Verified the hard way —
  without the check, the last line of init.scm dies on gen 1.
- The macro reloads if present and then ALWAYS imports: `reload-module`
  does not import, so gen 2+ would otherwise get nothing. Guile's own
  modules (the five stdlib ones) use plain `use-modules` — `reload-module`
  on one is an error, not a refresh.
- The umbrella is LOADED but not IMPORTED, deliberately: importing it
  would make a config's environment depend on the re-export list, so a
  public name added to a family but not yet to the umbrella would go
  missing from configs.
- tests/t-generation.sh pins it, asserting the generation's own USE-LIST
  rather than that a call works. Guile resolves names through a used
  module's use-list transitively, so with the old order the generation
  still REACHES everything and the whole rest of the suite passes — only
  the use-list shows it. Verified to fail by restoring the old order
  (names all 18 missing modules).
- tools/load-check.scm mirrors the new order: the generation is made
  before init.scm and is the module init.scm is read in.
- FIVE dead hl:: helpers removed from Guile.hpp/Guile.cpp, with the
  private thunks and includes that only they used (callThunk0,
  moduleCall1Thunk, ModuleCall, <sstream>, <vector>):
    useModule   — orphaned by this work: the import list moved into
                  init.scm and no caller was left
    exportAll   — the kernel exports by #:export now, not module-export-all!
    resolveModule — a byte-for-byte duplicate of makeModule, which superseded it
    loadModule  — init.scm loads modules by name
    call0       — nothing makes a 0-arg contained call
  The last four were already dead before this work. Kept: the
  define-module-expands-in-the-CURRENT-module insight, which is live
  (load-check.scm implements it) and now lives in CLAUDE.md with
  loadModule marked dead rather than as a claim about live code.
- tools/bind-audit.py now REPORTS dead helper declarations in Guile.hpp,
  so this class cannot silently re-accumulate. Verified to fail: adding
  `SCM nothingCallsThis(const char*)` trips it, exit 1, naming the
  offender. The check is exact (hl::-qualified mentions only) precisely
  because a bare-name search matches same-named members across the tree
  and would be disabled as noisy.
- makeModule's comment corrected: it claimed `#:ensure` is what makes it
  create on a miss. It is the C entry point scm_c_resolve_module, which
  has no such argument — it creates on a miss AND autoloads.

== THE UMBRELLA IS GONE; THE API IS DERIVED ==
- hyprscheme.scm `(hyprscheme)` is DELETED. It was a curated #:re-export
  list and "the single source of truth for what is public". Same lesson
  as the Host.cpp list: a hand-kept list of what is public drifts from
  what is public, and this one had — it listed hl-bind-thunk and
  hl-bind-tokens, two internal record accessors, and those were the ONLY
  two names it had that the modules did not.
- THE PUBLIC SET IS DERIVED BY ASKING GUILE. tools/api-names.scm loads
  the machinery as the host does (stub the gsubrs, make a generation
  current, load init.scm) and reads each module's
  module-public-interface — which cannot disagree with the code. 323
  names. No list anywhere.
- What counts as API: every module init.scm names, EXCEPT the kernel
  (the C++ boundary — 368 exports, 313 hl--c-* gsubrs). Extras and
  emacs-keymaps ARE API: extended API rather than base, but a config
  calls hl-kbd and hl-gesture-add! directly and they follow the same
  testing rule. Internals are excluded by the convention the tree
  already keeps: hl--* internal, *-rtd a record type C++ resolves by
  name, make-hl-* a record constructor. A name that is none of those
  and starts with hl- IS API — if it should not be, RENAME it, do not
  filter it. That is what happened to the leaked pair:
  hl-bind-thunk/hl-bind-tokens -> hl--bind-thunk/hl--bind-tokens.
- t-coverage.sh now derives from api-names.scm instead of sed-scraping
  the umbrella. Both guards verified to fail: an injected untested API
  name is reported by name, and an empty derivation trips the 200-name
  vacuity floor (which matters more now — a failed load yields an empty
  list rather than an error).
- Consumers rewired: doc-audit.py (glob the modules), doc-exercise.scm
  (shadow registrars across the modules, not one interface),
  module-audit.py (the PUBLIC: check was "every public name reaches the
  umbrella" — vacuous without it, so it now derives the set and keeps a
  size floor; the ENTRY: check stays), load-check.scm, compile-lint.scm,
  bind-audit.py, Makefile (SCM_FILES, install, scm-compile).
- Docs: CLAUDE.md's umbrella section rewritten as "THERE IS NO UMBRELLA"
  with the derivation rule; the stale `hyprscheme/api.scm` /
  `(hyprscheme api)` references in Host.cpp and CLAUDE.md removed (that
  module never existed); the wiki's building-the-plugin layout updated.
  FABLE.md / FABLE-DONE.md deliberately NOT touched — they are the
  historical design record and describe the state at a point in time.

== TESTS + TOOLING ==
- hl-load-config (in extras): load another config file by name.
  Looks under $XDG_CONFIG_HOME/hypr/ then $HOME/.config/hypr/, appending
  .scm unless the name already ends in it, and loads it INTO THE CURRENT
  GENERATION via hl--load (the kernel's `load` shadow) so what it
