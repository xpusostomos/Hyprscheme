== HANDLE MODEL (implemented + runtime-verified 2026-09-18) ==
The string-payload design was replaced by upstream's handle model, per
agreed decisions (break OK; handles+selectors accepted; *-info deleted;
workspace-removed born dead; input alists stay):
- Workspace and monitor handles join window handles: opaque records
  wrapping an int id (define-record-type hl-workspace / hl-monitor),
  backed by weak-ref registries (g_workspaces / g_monitors). Fresh handle
  per hand-out; identity via hl-workspace=? / hl-monitor=?; staleness via
  hl-workspace-alive? / hl-monitor-alive?; every getter on a stale handle
  returns #f.
- Getters mirror upstream Lua's object fields 1:1 (LuaWorkspace.cpp /
  LuaMonitor.cpp): hl-workspace-{name,addressable-name,number,monitor,
  special?,active?,visible?,empty?,persistent?,has-urgent?,has-fullscreen?,
  fullscreen-mode,fullscreen-window,last-window,window-count,group-count,
  tiled-layout} and hl-monitor-{name,description,number,enabled?,focused?,
  x,y,width,height,scale,transform,refresh-rate,mode,dpms?,vrr?,10bit?,
  reserved,mirror-of,active-workspace,active-special-workspace}.
  hl-workspace-info and hl-monitor-info are DELETED, replaced by these.
- Handles are accepted anywhere a selector string is, via the selector
  bridges (hl--ws-arg / hl--mon-arg -> hl-workspace-selector /
  hl-monitor-selector) — the same object-to-selector conversion upstream's
  workspaceSelectorFromLuaSelectorOrObject performs.
- Events now deliver handles: hl-on-workspace-active/-created/-special-
  active/-move-to-monitor, hl-on-monitor-added/-removed/-focused, and the
  special-active / move-to-monitor payloads are (ws mon) handle pairs with
  #f for an absent workspace (upstream nil parity). window.open_early /
  kill / bell / update_rules wrappers (which 9-12) landed with this batch.
  config.props_refreshed delivers #t/#f (hl-on-config-props-refreshed).
- hl-workspace-change-id (CA::changeWorkspaceID) is wired and exposed.
- Built clean; prelude loads and bootstrap compiles under bare Chez; all
  foreign-procedure symbols cross-checked against Sregister_symbol.
  RUNTIME VERIFIED 2026-09-18: the full test suite passes 7/7 against a
  nested compositor, plus live probes of the new surface (getters,
  handle collections, window->workspace handle chains, handles as
  selectors, identity across calls, event registration for the new
  events). Wiki updated: events.md, scheme-utilities.md, dispatchers.md,
  code-snippets.md (four snippets rewritten to the handle API).

== PER-GENERATION ENVIRONMENTS (implemented + verified 2026-09-18) ==
Each config reload now evaluates in a FRESH Chez environment (a copy of
  the persistent interaction environment made by hl--reset), so orphaned
  definitions from previous generations cannot leak — consistency with
  upstream's per-reload fresh lua_State. Verified live: an eval-defined
  orphan and a load-split file's definitions both disappear on reload;
  hl--state survives; the watchdog (t-watchdog) passes with per-generation
  budget overrides.
Mechanics:
- hl--reset: clears hl--binds, clears the hl--generation slot (breaks the
  reference chain so old generations are collectable), installs a fresh
  copy of the persistent environment.
- hl--load evaluates the config into (hl--target-env); hyprctl scheme
  evals land in the current generation too (they die with it, like
  upstream's evals).
- load/eval are SHADOWED once in the persistent environment to target the
  current generation — otherwise the documented config-splitting workflow
  (load "keybinds.scm") would leak into the persistent env. The
  interaction environment permits redefining imported names.
- hl--wd-enter reads hl--watchdog-ms through the CURRENT generation
  (config and hyprctl set!s land in the generation copy; the machinery's
  own defining environment would never see them).
PROCESS NOTE (an honest record): the first attempt was reverted on a
  misdiagnosis. "Minimal repros" of a Chez deadlock were BROKEN — they
  installed a timer-interrupt handler but never ARMED the timer (the only
  set-timer call was inside the handler), so the handler never ran and
  the runaway loop froze regardless of environment arguments. With the
  timer armed, escapes through copy-environment targets work identically
  to the interaction environment. The real issue all along was the budget
  shadowing above. (Also learned the hard way: one-line bash exports
  expand later assignments with the OLD value of an earlier variable — a
  probe exported HYPRSCHEME_CONFIG=$XDG_CONFIG_HOME/... in the same
  statement that set XDG_CONFIG_HOME, silently pointing the override at
  the user's real config.)

== VISIBILITY=HIDDEN BUG (root-caused + fixed 2026-09-19) ==
The Makefile compiled the plugin with -fvisibility=hidden. Inline global
  variables in Hyprland headers (g_pEventLoopManager, g_pTrackpadGestures,
  ...) then compiled as HIDDEN LOCAL copies inside the .so: the plugin read
  its own never-assigned copy (g_pEventLoopManager was always NULL, el=0x0)
  instead of the compositor's. Effects: the socket1 "scheme" command was
  silently skipped on config-load-time plugin init (the `if (sock())` guard
  failed), timers registered into a dead event-loop copy (hl-after/hl-repeat
  returned ids but could never fire), gestures likewise. Everything reached
  through accessor FUNCTIONS (Event::bus(), IPC::Socket1::sock(),
  Keybinds::mgr(), Animation::mgr()) always worked — which masked the bug
  for weeks. Fixed by dropping -fvisibility=hidden from CXXFLAGS: inline
  variables now compile as GNU-unique symbols (nm class u) merged with the
  executable's. t-api now also VERIFIES a timer actually fires.
Debug-log affordances added: registerIpc entry log, handler-entry log
  (both temporary; keep or remove later), tests/run.sh KEEP=1 to preserve
  the compositor workdir for post-mortems.
OLD MYSTERY EXPLAINED: the "deferred doLater variant never fired its
  callback" comment at the socket registration — doLater went to the dead
  event-loop copy. The 10/10 suites passed because no test verified that a
  timer or bind actually FIRED — only that registration returned ids.

== HL-BIND LIST-ONLY API (implemented + verified 2026-09-19) ==
hl-bind dropped the runtime shape-dispatch: the ONLY calling convention
  is (hl-bind TOKENS THUNK . OPTS) where TOKENS is a list of key tokens
  (mods first, key last). kbd/hl-kbd build the list; users who want the
  old two-string shorthand define it on top (binds.md shows a wrapper).

  through the two-string branch is gone with the branch. t-api.sh covers
  the literal list, kbd single-key and bracketed-key forms.
Tests use emacs-canonical function-key spelling (kbd "s-<F16>");
  verified against Hyprland's XKB_KEYSYM_CASE_INSENSITIVE resolution —
  "<f16>" and "F16" bind the same keysym (src/keybinds/Key.cpp).
Docs (binds, submaps, bind-flags, code-snippets, device-*, layouts,
  dispatchers, scheme-utilities, naming-conventions) swept to the list
  form; kbd examples corrected to the actual token lists (they showed
  (mods . key) pairs and claimed <f1> -> "F1"; the token is "f1").
Bounded-value APIs document the schemey form only: directions are
  'left/'right/'up/'down (strings still parse, undocumented).

== BINDS: auto-consuming protocol (RESOLVED 2026-09-19 — see batch above) ==
