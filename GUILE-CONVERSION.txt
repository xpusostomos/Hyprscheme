GUILE-CONVERSION.txt — the Chez → Guile investigation (Sep 2026)

Everything below was VERIFIED LIVE on Guile 3.0.11 (the machine has
guile + guile-3.0.pc). Scratch probes live in /tmp/guile-spike,
/tmp/guile-gc.cpp, /tmp/guile-defun.scm; do not trust claims not
backed by a probe. Nothing in the repo changed for this file.

WHY: Chris is weighing whether Chez was the wrong extension-language
choice — Guile has a much bigger third-party/community ecosystem.
Outcome of the investigation: migration is doable, mostly mechanical,
and the plan below starts by splitting generic vs Chez-specific code
WHILE STILL RUNNING CHEZ, then builds an alternate backend, committing
at each point so we can move backwards.

==================================================================
1. WHAT ACTUALLY SPLITS (quantified)
==================================================================

C++ side (SchemeManager.cpp + SchemeLayout.cpp + SThunkRef.hpp):
- 686 Chez C-API call sites, but only ~15 DISTINCT functions:
  Sregister_symbol (298 sites), Sfalse/Strue, Sstring_to_symbol,
  Sstring/Sstring_utf8, Stop_level_value, Scall0..3, Sfixnump,
  Sboolean_value, marshRoot/marshRelease/SThunkRef (87 lines).
- => the whole C++ port funnels through a thin host abstraction of
  ~15 ops (eval string/file, register function, call closure, catch,
  box/unbox). Nothing else in the C++ side knows Chez exists.

Scheme side (the 3 .scm files):
- hyprscheme-bootstrap.scm: 299 foreign-procedure declarations
  (153 typed scheme-object, 146 plain int/string/double) + the
  entire hl-* API which is plain portable Scheme (~2000 lines).
- prelude/defun: dialect surface is small (see table below).

The API layer (handles, binds, rules, events, gestures, layouts) is
backend-agnostic by construction — it does not need rewriting.

==================================================================
2. GUILE FFI — verified working (spike /tmp/guile-spike)
==================================================================

All four plugin-shaped mechanics passed:

a. C++ -> Scheme primitive registration: scm_c_define_gsubr (analog of
   Sregister_symbol). All args arrive as SCM; C++ unboxes
   (scm_to_int/scm_to_locale_string/...).
b. C++ calling Scheme closures: scm_call_0/1/...; errors contained
   from C++ via scm_c_catch (the hl--report analog works).
c. Typed Scheme->C FFI: (use-modules (system foreign)) then
   (pointer->procedure RET-TYPE (dynamic-func "name" handle)
    (list ARG-TYPES...)) — 1:1 replacement for plain-typed
   foreign-procedure. int/double/string all worked.
d. Embedding in a shared lib: works (that is the plugin's shape).

The 299 foreign-procedure declarations split into two kinds:
- 146 plain-typed: mechanical pointer->procedure rewrite (1:1), OR
  also make them gsubrs for uniformity.
- 153 scheme-object-typed (all the handle/record APIs): NO Guile FFI
  type exists for SCM. These become gsubrs — ~153 thin unboxing shims
  in C++ (mechanical; scm_to_* on entry, wrap in SCM on return).
  Uniform alternative: ALL 298 as gsubrs; Scheme-side foreign
  declarations then just disappear (gsubr = a normal binding).

GC protection for C++-held values (the marshRoot analog): verified —
scm_gc_protect_object / scm_gc_unprotect_object. C++-held closures
survived 50 forced GC cycles, stayed callable from both C++ and
Scheme-side gsubr calls, state advanced correctly. GOTCHA LEARNED:
protecting an immediate (a fixnum) corrupts GC state and later
SIGILLs the process — protect heap objects only. SThunkRef/marshRoot
map onto this directly.

==================================================================
3. THE THINGS I CALLED "GENUINELY HARD" — RESEARCHED, MOSTLY DEMOTED
==================================================================

i. Generation model (copy-environment) — WAS LISTED HARD, IS NOT.
   Guile's environment objects are modules, and (guile) exports the
   full manipulation toolbox: make-fresh-user-module, module-define!,
   module-for-each, module-set!, module-use!, set-current-module,
   interaction-environment. There is no one-call copy-environment,
   but a 10-line helper reproduces Chez semantics exactly, ALL SIX
   properties verified live:
     1. generation code sees the persistent API
     2. user definitions stay in the generation
     3. set! inside a generation works, does NOT leak back
        (fresh locations, shared values — same as Chez)
     4. generations independent of each other
     5. mutable values shared across the copy (hl--state bridge)
   (define (copy-module src)
     (let ((dst (make-fresh-user-module)))
       (module-for-each (lambda (sym var)
                          (module-define! dst sym (variable-ref var)))
                        src)
       dst))
   TRAP: the naive Guile-native design — fresh module that
   module-use!s the API interface — has WRONG semantics: used
   interfaces share variable locations, so set! in a generation
   leaks into the persistent API. Use the explicit copy.
   Work remaining: helper + rewrite of hl--reset + the load/eval
   shadows. Not a redesign.

ii. Guardians — WAS LISTED HARD, IS NOT. make-guardian EXISTS in
   Guile (verified), plus weak tables. The handle-reaping design
   carries over nearly as-is.

iii. GC plumbing — verified above (scm_gc_protect_object).

iv. defun machinery — verified: Guile's expander substitutes pattern
   variables INSIDE (quote ...) in templates IDENTICALLY to Chez
   (the exact production macro from hyprscheme-defun.scm ran
   unchanged on Guile; metadata captured correctly: 'args → the
   arglist, 'doc → the docstring). syntax-case is supported.
   Re-verify describe-function end-to-end during migration, but no
   rework expected.

v. Watchdog — the real mechanism today is Chez's timer interrupts
   (set-timer / timer-interrupt-handler / current-time /
   time-nanosecond) in the prelude's hl--wd-enter/exit. Guile's
   equivalent is sigaction + Guile asyncs: a SIGALRM handler throws
   and catch unwinds a TIGHT infinite Scheme loop — verified live
   (asyncs deliver at procedure-entry safe points, and the VM hits
   them in a self-recursive loop). Same recovery semantics via
   call/cc escape. Chez's time functions map to (current-time).
   Foreign calls remain non-interruptible on both backends (C++
   log-only watchdog thread stays as the backstop).

vi. Crash-reporter signal interplay — the ONE genuinely unverified
   item. Guile installs its own signal handlers (notably a SIGSEGV
   handler for stack-overflow detection; libgc may use internal
   signals). Today's plugin re-installs handlers to route crashes to
   Hyprland's CrashReporter::createAndSaveCrash. Must re-verify the
   coexistence on Guile during migration; not spike-testable.

Also discovered: Guile's reader opens a block comment at `#!` — any
user config using Chez-style `#!optional`/`#!key`/`#!rest` lambda
keywords would silently comment things out. Our codebase uses NO
lambda-list keywords (only the 10 `#!eof`s), but this is a user-config
landmine to document in the wiki if we move.

Also: GUILE_AUTO_COMPILE=0 for tests (avoid ~/.cache/guile writes in
nested-test environments; observed the cache write during probing).

==================================================================
5. TRADE-OFFS (what Guile buys, what we give up)
==================================================================

Buys:
- Batteries: srfi-1/13/69, ice-9 modules, regex, guile-json etc;
  official embedding documentation; bigger community. (For THIS
  program the actual consumption would be modest — the hl-* API is
  the library — but user-written helper libraries become plausible.)
- The build SHRINKS: no PIC kernel, no boot files, no BUILDCHEZ.md,
  no in-place Chez tree. `pkg-config guile-3.0` — same pattern as the
  lua55 we already consume for Hyprland's config.
- 299 foreign-procedure declarations deleted.

Gives up:
- Self-containment: today the plugin statically embeds its
  interpreter; with Guile it depends on the system's libguile-3.0 +
  its runtime modules. This matches how Hyprland consumes liblua, but
  it is a different deployment model. Chez speed is also lost (Guile 3
  JIT is decent; irrelevant for config scripting).
- ABI stability: libguile-3.0 soname is stable within 3.0.x; 4.0 will
  break the C API (new rebuild, like Hyprland header churn).
- License: LGPL vs Chez's Apache (footnote, not a blocker).

6. MIGRATION PLAN (commit at each point, per Chris)
==================================================================

1. C++ host abstraction FIRST, while still on Chez: a thin
   SchemeHost interface (~15 ops: init, eval string/file, register
   function, call closure N-ary, catch, box/unbox, datum-to-string).
   Port SchemeManager/Layout onto it with ZERO behavior change; suite
   stays 12/12. COMMIT.
2. DONE (Sep 2026). Guile backend: SchemeHostGuile.cpp + the
   declarative foreign-procedure shim (hyprscheme-compat-guile.scm)
   — NO per-function gsubr shims needed: the C++ host registers typed
   function pointers via scm_from_pointer, and the compat layer's
   foreign-procedure syntax attaches type conversions declaratively
   (scheme-object crosses as its raw word through the FFI as
   uintptr_t, verified in /tmp probes). `make BACKEND=guile` selects
   the backend. Smoke test green: plugin loads, prelude -> compat ->
   defun -> bootstrap chain reaches hl--ready #t, evals, foreign
   calls, error containment and describe-function all work, clean
   log. STILL OPEN on the Guile side (steps 3-5): config reload
   (copy-environment wired but untested), guardian drain (no
   collect-request-hook yet), watchdog (stubbed), full suite.
   COMMIT.
3. IN PROGRESS (Sep 25). The Guile machinery now BOOTS and the eval
   channel works (hl--eval, describe-function, foreign calls, query
   getters all answer). Compat-layer fixes landed so far, each found
   by the suite:
   - curried (define-syntax (name x) ...) is CHEZ-only; Guile wants a
     plain lambda transformer
   - (system foreign) must be imported (uintptr_t/int32/...) — AND it
     exports `void` = the ffi type = the integer 0, which the prelude's
     (void) then APPLIES ("Wrong type to apply: (0)" killed every
     eval); capture the type as hl--ffi-void-type and rebind (void)
   - Chez's (format "fmt" ...) has no destination; Guile's does — a
     Chez-style format wrapper
   - (srfi srfi-9) for define-record-type, plus a compat macro
     translating Chez's (fields ...) shorthand (names preserved:
     make-<n>, <n>?, <n>-<field>); srfi-9 aliased via a RENAMED
     import (Guile has no (define-syntax new old) aliasing)
   - R6RS exists/for-all = srfi-1 any/every
   - generations must copy the source module's IMPORTS too
     (module-use! of (module-uses src)) — locals alone miss guard,
     the rnrs tables, srfi-13
   - Guile's default error port does not reach the compositor's
     stderr in this embedded context; compat rebinds
     current-error-port to (open-file "/dev/stderr" "a") — APPEND
     mode, "w" truncates the compositor's own log!
   - plugin sets GUILE_AUTO_COMPILE=0 before scm_init_guile; the
     suite exports it too
   STEP 3 COMPLETE (Sep 25, later session): SUITE 12/12 ON GUILE,
   chez 12/12 unchanged. The remaining fixes, each caught by the suite:
   - srfi-9's constructor/accessors are SYNTAX TRANSFORMERS — unappliable
     as values, and code compiled BEFORE the record exists (bootstrap
     defines hl-bind-add! long before the hl-bind record) applies them
     and dies. The compat define-record-type now expands DIRECTLY onto
     Guile's core record primitives (make-record-type/make-struct/
     struct-ref): every generated binding is a plain procedure, so
     forward references late-bind exactly like Chez. NAME binds to the
     rtd, matching srfi-9.
   - boot-9's (error msg args...) stores msg as a "~A ~S" TEMPLATE with
     args as irritants (string-join at boot-9:2052) — display-condition
     must render the template against the irritants, or reports show
     the literal "~A".
   - THE WATCHDOG: ported via sigaction SIGALRM + Guile asyncs (deliver
     at procedure-entry safe points). Interface parity: timer-interrupt-
     handler reads/installs, set-timer arms via alarm() and returns the
     previous value. t-watchdog passes.
   - THE LOG-CORRUPTION BUG: (open-file "/dev/stderr" ...) reopens the
     log with a FRESH WRITE OFFSET — error lines OVERWROTE the log's
     beginning (the t-zz-example "1 -> 0" failures; error lines vanished
     mid-suite). Fixed with (fdopen 2 "w"): one shared write offset with
     the compositor's own writes.
   - Chez's contract "FOREIGN CALLS ARE NOT INTERRUPTIBLE": a SIGALRM
     async fired inside the compositor's C++ code (crash in
     CWindow::~CWindow ← CFocusState::window, libguile frames in the
     stack — crash report 7171). Fixed: the foreign-procedure shim wraps
     every foreign call in call-with-blocked-asyncs, so watchdog escapes
     happen only when control returns to Scheme, exactly like Chez.
   - C++ side: contained calls (scm_c_catch around call0-3 — errors
     print via fd 2 and return False, never unwinding through C++
     frames); SchemeHost::truthy/word restored in the Guile host after
     a regex edit ate them (a MISSING EXPORT = lazy symbol failure at
     first use: "symbol lookup error ... undefined symbol truthy").
   - Loader cleanup: no more write(2) breadcrumbs; compat loads first,
     prelude next, machinery check on hl--load only, defun + bootstrap
     through the guarded hl--load.
   - THE GUARDIAN DRAIN: Guile HAS the analog — after-gc-hook runs after
     each collection, and the bootstrap's hl--handle-guardian +
     hl--drain-handles! port as-is (the earlier "Guile has no such hook"
     was wrong; after-gc-hook exists in 3.0.11). The hook runs only the
     drain (the Chez handler's trailing (collect) would re-enter gc from
     inside the hook), no-ops until the bootstrap defines it (module-
     variable check), and a failing drain reports instead of killing the
     GC trigger. Verified: counting hook fires per gc in the compositor.
   REMAINING on the Guile path: crash-reporter interplay (step 5,
   unverified), longer soak, plugin LOG() still swallowed (upstream).
   COMMIT.
4. GC plumbing swap: marshRoot/SThunkRef -> protect/unprotect (or a
   Scheme-side registry); guardians verified native. COMMIT.
5. Watchdog port: set-timer/timer-interrupt-handler -> sigaction
   SIGALRM + asyncs + call/cc escape; C++ log thread unchanged.
   Crash-reporter interplay re-verified here (the open item).
   COMMIT.
6. Build/install: drop BUILDCHEZ.md, CHEZ_DIR, boot files, PIC
   kernel; pkg-config guile-3.0; keep .scm-files-next-to-plugin
   design (backend-independent). Tests + soak through the suite.
   COMMIT.

The 12-file suite + soak harness are backend-agnostic and carry the
whole migration — they are why this is tractable.

Size estimate: steps 3-4 mechanical days; step 2 a few days; steps 1
and 5 hold the unknowns. Risk profile better than first reported
(two of the three original "hard" items turned out portable with a
small helper, verified above).
